# Concord 사업 방향·원칙 정리

> 출처: 2026-06-16 ~ 07-13 세션 지시문 467건(docs/session-instructions.md) + 오너 확정 메모리.
> 오너(대표)가 직접 지시한 내용에서 추출한 사업 목표·이상·원칙의 종합본.

---

## 1. 사업 정체성

- **Concord** — 프리미엄 1:1 방문(대면) 과외 매칭·관리 플랫폼.
- 핵심 슬로건 방향: **"선생님이 다릅니다"** (히어로 카피, 한 줄).
- 단순 매칭 중개가 아니라 **매니저가 상담→배정→사후관리까지 밀착 운영**하는 관리형 과외.
- 서비스 지역: **서울(구·법정동·인접 지하철역), 동탄(행정동 단위)**.
- 대상: 중·고등학생. 이해관계자 4역할 — 학생 / 학부모 / 선생님 / 매니저(+치프매니저).

## 2. 사업의 이상 (오너가 명시한 목표)

> "학생의 공부 스타일과 맞는 교육 철학의 선생님을 추천해준다는 게 제일 핵심 포인트." (07-06)

- **성향 매칭 철학**:
  - 활발한 학생 → 카리스마 있는 선생님
  - 롤모델이 필요한 외동 학생 → 존경할 만한 인품의 선생님
  - 게으른 학생 → 성실한 선생님이 본보기
  - 여린 학생 → 친절하고 착한 선생님
- **안전·신뢰**: "안전하고 믿을만한 선생님이 배정된다"가 두 번째 축.
  - 대표가 **전원 직접 대면 면접** — 인품·학력·신원·수업 실력 4가지 검증.
  - 단, 검증은 마케팅의 **메인이 아니라 '요소' 중 하나**로 배치 (07-07 결정 — 타사와 검증 수준이 크게 다르지 않다는 자기인식, 공포마케팅 과잉 경계).
- **수업 밖 관리가 성적을 가른다**: "수업보다도 수업 이후 학생의 공부가 성적을 가릅니다."
  - 매 수업 숙제·공부계획을 시스템에 등록, 학생이 매일 체크.
  - 질문은 최고성능 전용 AI가 즉시 답변 + 이어서 선생님 답변.
  - 매월 선생님이 직접 리포트 작성, 학생·학부모와 숨김 없이 공유.
- **불만족 리스크 제거**: 첫 수업이 맞지 않으면 100% 환불, 선생님 교체 비용 0원, 배정 후에도 매니저 상시 관리·언제든 상담 요청 가능.

## 3. 서비스 흐름 (North Star)

1. 학생 신청 또는 결제.
2. 신청만 한 학생 → 매니저 배정 대기 상태.
3. 결제한 학생 → **치프매니저에게 자동 배정**.
4. 매니저가 배정받아 **방문 상담** 일정 조율 — 상담에서 학생 성향 파악 + 학습 진단 제공.
5. 상담 중 매니저가 **적합한 선생님을 자유 배정**. (앱 내 학생 수락 버튼은 **형식** — 마케팅·UI에서 절대 강조 금지. 거절/재배정 플로우는 학생 측에 만들지 않음. 재배정은 매니저 권한.)
6. 선생님이 첫 수업일 지정 → 수업 시작.
7. 숙제: 선생님이 1주(또는 4일) 분량을 **한 번에 입력하면 요일별 가중 자동 분배**. 반복 패턴은 템플릿으로 재사용.
8. 수업 확인: 자동완료 폐지 — 선생님이 완료/사유 선택. 학생 과실=정산 포함, 비과실=마지막 수업으로 이월, 3자(학생·학부모·매니저) 알림.
9. 구독 일시정지(paused): 학부모에게 **노출하지 않는** 제도. 불가피한 요청 시 매니저가 수동 처리, 이후 마찰 없이 재개.

## 4. 제품 우선순위

- **앱이 우선, 웹은 보조** (07-12 명시).
- 역할기반 단일 앱: 학생·학부모·선생님·매니저 모두 앱 사용.
- 학부모 모드가 최대 갭 → 1단계: PARENT 계정, 자녀 연결은 **코드/QR 2옵션 + 매니저 수동 연결**, 결제는 학부모·학생 양측 가능, 학부모 권한은 액션도 가능.
- 학부모 **웹**은 리포트·결제·상담만 (진도/숙제 불가).
- 학부모 앱 = 수업·숙제·진도 열람용이라는 점을 홈에서 소개.

## 5. 요금 철학

- **할인 구조·요금 공식 없음.** "소비자 심리에 최적화된 금액으로 내가 골랐다" — 오너 직접 설정, AI의 구조 제안·금액 변경 금지.
- 확정가(중등|고등, 만원): 주1회 2h **38|43**, 주1회 3h **55|58**, 주2회 2h **76|78**, 주2회 3h **106|112** — **코드값이 진실.**
- 표기: "월"이 아니라 **"(4주)"** 단위. "주 1회·3시간"처럼 간결하게. 총 시간 환산 계산 금지.
- 요금제 카드: 한 줄 배치(절대 두 줄 금지), 황금비율, 할인률 뱃지 없음.
- 부제 방향: "첫 수업이 맞지 않으면 100% 환불 / 선생님 교체 비용 0원" + 각주 "*환불정책 참고".

## 6. 마케팅·카피 원칙

- **톤: 수능선배(suneungsunbae.com) 스타일** — 헤드라인은 확언체, CTA는 해요체 투트랙.
- **절제가 최우선**: "최소한 쓰고 절제된 톤으로. 왜 자꾸 말이 길어지고 모든 내용을 다 적으려고 하냐" (07-08). 문장은 삭제 우선, 조건·단서는 본문이 아닌 각주로.
- **"짜침"(싸구려 느낌) 절대 배제** — 검정 배너, 설명식 문구, 과한 뱃지 등 제거 대상.
- 공포 마케팅(과외 사고 뉴스 스크롤텔링)은 사용하되:
  - 뉴스 헤드라인은 **원문 그대로**, 3개만, 실명 마스킹.
  - "이런 일들이 실제로 있었습니다" 같은 설명 문구 금지 — 담백한 공감 문구만.
  - 스킵 허용, 세션당 1회 재생, 총 7초대로 압축 — 임팩트와 사용자 통제감 균형.
- **후기**: 전부 다른 사람이 쓴 것처럼 말투 각각 다르게. 반말체 금지. "기존 과외는 ~이 불만 → 지금은 ~이 좋다" 구조 활용. 성향 매칭·안전 가치가 스며들게. 실제 학원 후기 말투 학습 후 작성. (파일럿 전까지 임시, 실 후기로 교체 예정.)
- **신뢰 요소**: 실사 수준 인물 사진(직접 촬영분 우선), 대학 합격 로고(설카포·연고·서성한·중앙·경희·외대·이대), 인터뷰 카드.
- 참고 사이트: index.seoltab.com (구조·모객), class.qanda.ai, suneungsunbae.com (톤·UI 점잖음).
- 마케팅 우선순위: **1. 학생 2. 학부모 3. 선생님 채용 4. 매니저 채용**.
- 상담 전환 최우선: 신청 폼은 화면 위 가벼운 카드, **버튼까지 한 눈에** 들어와야 함(이탈 방지). "상담 신청만 해도 학습 전문가의 1:1 학습진단 제공."
- 채널: 카카오톡 채널(pf.kakao.com/_xlxcjwX) 상담 연동, 알림톡 도입 예정.

## 7. 디자인 원칙

- **디자인을 다시 만들지 말 것** — 디자이너 핸드오프 CSS를 한 글자도 안 고치고 그대로 import. 값 눈대중 이식 금지, 토큰 변수만 사용, 아이콘은 icons.js 단일 소스, Pretendard 1.3.9 고정, word-break:keep-all·tabular-nums 필수.
- **신 디자인 적용 범위 = 로그인 후 화면(포털·앱)만.** 공개 페이지(홈·pricing·tutors·reviews·faq·login) 수정 절대 금지.
- **신규 화면은 기능+뼈대만** 구현 — 폴리시는 디자인 AI에 핸드오프.
- **기능 축소 절대 금지**: 시안이 기존 기능보다 단순하면 축소 구현하지 말고 기능 보존형 재시안 요청.
- 사진: 원본 비율 유지(크롭·비율 왜곡 금지), 리사이징만 허용, 카드용은 1:1, 성별-이름 일치.
- 캐러셀은 좌우 이동만. 테마: 그린/블루 × 라이트/다크 4조합.
- 기존 디자인은 삭제·덮어쓰기 금지 — 언제든 롤백 가능하게 보존.

## 8. 법률·리스크 스탠스

- 법률 문서는 **플레이스홀더 + 추후 실제 자문** — AI가 법률 조항 창작 금지.
- 학부모 동의는 **"동의 간주" 고지 문구**로만 — 보호자 SMS 인증·전자서명·복잡한 미성년 분기 등 무거운 동의 플로우 금지.
- 앱 내 후기/평점 직접 수집 기능 금지.
- 학부모 연락처는 가입/결제/상담 후 매니저에게 전달되는 최소 구조.
- 결제는 서버측 Toss confirm·금액 검증·멱등성 필수 — 프로덕션에서 가짜 결제 완료 절대 불가.

## 9. 운영·개발 방식 (오너의 일하는 원칙)

- **작게 자르고 검증**: 슬라이스 단위 구현 → lint/tsc/build → 커밋. "Do not push" 기본, 푸시는 명시 지시.
- **파일럿 반복 검증**: 서브에이전트로 학생·학부모·매니저 가상 가입/민원 → 오류 0까지 반복. API 직접 호출이 아니라 **실제 버튼 클릭 순회**로 UX 마찰 확인.
- **위임 원칙**: 설계·중요 판단은 메인, 단순 코딩은 opus 서브에이전트·codex(토큰 여유)에 적극 위임, diff로 검증.
- **문서화 집착**: 핸드오프(다른 AI가 언제든 인계 가능한 수준), IR 덱·브랜드 가이드라인·원페이저, 사업계획서·재무계획(창업지원사업 제출용), 기각된 제안도 요약 보존. 문서 통합 시 **내용 축약 금지**.
- 사업 분석 요구 패턴: "성공할 수밖에 없는 사업" 목표로 리스크·고도화 방안 수십 개 단위 발굴 → 실행 분담(AI가 할 것 / 경영자가 할 것 구분).
- 오버엔지니어링 경계: 유지보수를 위한 유지보수 금지, 기능 개발 속도와 안정성 균형 (07-05 진단 지시).

## 10. 대외 목표

- **투자 유치·창업지원사업 지원**이 문서화의 목표 (IR 덱, 사업계획서, 재무계획).
- 아직 정식 출시 전 — 더미 데이터 존재 인지, 출시 전 오너가 직접 최종 점검(법률·후기·더미 교체).

## 11. 심층: 지시가 추구하는 것 — AI와의 반복 갭 분석

> 교정 지시 패턴에서 역추론한 오너 세계관. AI 협업자는 이 절을 기본값 보정표로 사용할 것.

### 관통 논제: "판단의 위임"을 파는 사업

상품은 과외가 아니라 **"학부모가 더 이상 비교·검증·선택하지 않아도 된다"는 안도감**.
매니저가 정해주고 대표가 걸러준다 — 선택 피로의 제거가 상품.
AI의 학습 기반은 마켓플레이스 문법(선택지·수락/거절·평점·비교·할인)이라 **선택권을 주는 UX를 무의식적으로 재삽입**하는 경향이 있고, 오너는 이를 반복 삭제해 왔다(수락 버튼 강조 금지, 거절/재배정 플로우 금지, 할인 구조 금지, 평점 수집 금지, 검증 배지 나열 제거).
**이곳은 플랫폼이 아니라 큐레이션 서비스다.**

### 반복 교정 8패턴 (AI 기본값 → 오너 원칙)

1. **완결성 → 절제**: 정보 많음≠품질. 프리미엄은 확언하고 침묵한다. 부연·조건 나열은 브랜드 훼손. "문장은 삭제 우선."
2. **리터럴 → 의도 추출**: 오너는 예시·참고 사이트·"이 느낌"으로 소통한다. 예시를 스펙으로 복사하지 말고 미학 규칙을 추상화해 적용할 것.
3. **재해석 → 재현**: 핸드오프는 영감이 아니라 사양. 취향 결정은 이미 끝났고 AI 역할은 충실한 이식. 창의 구간(신규 설계)과 복제 구간(핸드오프 구현)을 혼동하지 말 것.
4. **논리 정합성 → 심리 최적화**: 요금·카피에 수식적 일관성을 만들려 하지 말 것. 가격은 심리 신호이며 설명되지 않아도 된다.
5. **일회 지시 → 영속 헌법**: 오너의 결정은 세션이 바뀌어도 유효하다. 같은 교정을 두 번 받게 하지 말 것 (예: 요금제 카드 한 줄 배치 3회 재지시).
6. **자율성 비대칭**: 실행·과정 자율 100%("묻지 말고 끝까지"), 제품 취향 판단 자율 0%. 의견 제시는 환영하되 결정은 오너. 지시받은 범위 밖 "개선"을 실행에 끼워넣지 말 것.
7. **균질 출력 → 인간의 결**: 후기·카피는 각기 다른 사람의 질감이 필수. 평균 회귀한 매끈한 출력은 신뢰를 깎는다.
8. **자산 존중**: 레이아웃이 사진에 맞춘다(역 아님). 시안(스킨)이 기능(원본)을 깎을 수 없다. 원본 훼손(크롭·비율 왜곡·기능 축소·내용 축약) 금지.

### 메타 구조 둘

- **조직 설계 = 제품 설계 (동형)**: 학부모에게 "매니저가 정해준다"를 팔 듯, AI에게도 "오너가 정해준다"를 적용한다. AI의 판단 침범은 제품에서 수락 버튼을 강조하는 것과 같은 위반.
- **스펙이 아니라 반응으로 설계**: 오너는 살아있는 배포물에 반응하며 디자인한다. AI의 최적 역할은 빠르고·되돌릴 수 있고·충실한 초안 생산. "완성·확정"하려 들지 말 것.
