### 1.3 인증·인가

- **웹**: NextAuth v5, Credentials 단일 Provider(`identifier` = 이메일 또는 전화번호). 전화번호는 정규화 후 합성 이메일(`*@concord.local`) 또는 phone 컬럼 매칭. 소프트 삭제 계정은 로그인 차단. `NEXTAUTH_URL`에 경로를 붙이면 basePath 오염으로 전원 로그인 실패.
- **모바일**: 외부 라이브러리 없는 HMAC-SHA256 커스텀 JWT. Access 7일 / Refresh 60일, `Authorization: Bearer`.
- **미들웨어**: `/admin/*`은 ADMIN만. 로그인 학생은 공개 경로+`/dashboard`, 강사·매니저는 공개 경로+`/teacher-portal`로 유도. `CHIEF_MANAGER`의 UI 라우팅 분기는 미들웨어에 없음 `[미확인]`.
- **API 가드 헬퍼**: `requireStudent` / `requireTeacher`(TEACHER·MANAGER·CHIEF) / `requireManager`(MANAGER·CHIEF) / `requireManagerOrAbove`(+ADMIN) / `requireAdmin`(ADMIN·**CHIEF도 통과**) / `requireParent` / 모바일 대응 헬퍼(`requireMobileStudent`·`Parent`·`Teacher`·`TeacherAllowPending`·`Manager`·`User`).

### 1.4 DB 모델 요지

enum 6종: `UserRole`(ADMIN·CHIEF_MANAGER·MANAGER·TEACHER·STUDENT — PARENT는 07-12 추가 계열) · `ConsultationStatus` · `LessonStatus` · `SubscriptionStatus`(PAUSED 포함) · `MatchStatus` · `PaymentStatus`.

```
User ─1:1─ Student ─ OnboardingSurvey · BillingProfile · StudyPlan→StudyTask
      │            · QuestionMessage(구 Question은 DEPRECATED)
      │            · TeacherStudent(매칭) · ConsultationBooking→ConsultationReport
      │            · ManagerStudent · ManagerCareLog · Lesson · Subscription
      │            · PaymentCompletion(orderId unique=멱등키) · TokenWallet
      │            · MonthlyReport · SatisfactionCheckin · TutorReview
      ├─1:1─ Teacher ─ TeacherProfile · TutorAvailability · HomeworkTemplate
      ├─1:N─ Notification · PushDevice
독립: SiteContent · Testimonial · FaqItem(CMS) · AnalyticsEvent · AuditLog
```

- 매칭 활성 판단의 정책적 진리는 `isActive`(`matchStatus`는 병기).
- 결제 이력 무결성: `Subscription`·`PaymentCompletion`은 `onDelete: Restrict`.
- 주요 유니크: 학생–강사 1쌍 매칭, 학생당 강사 1리뷰, `BillingProfile.customerKey`, 강사 슬롯 중복 방지.

### 1.5 결제 흐름

1. `/checkout` Toss 위젯 → 승인 → `/success` 리다이렉트 → `POST /api/payments/complete`.
2. 서버가 `planIdFromAmount(amount)`로 요금제 재계산 — 클라이언트 값 미신뢰.
3. `completeStudentPayment()`: `orderId` 멱등 조회 → Toss `/v1/payments/confirm` 서버 확인 → Chief 매니저 자동 배정 → `Subscription` ACTIVE upsert → COMPLETED 클로즈. 실패 시 FAILED 기록.
4. 학부모 대납: `POST /api/parent/payments/complete` — 자녀 소유 검증 후 동일 로직 위임.
5. 빌링키: `register-success`에서 `customerKey === "student-{studentId}"` 검증 후 발급, `autorenew` 토글. 자동 청구 스케줄러 진입점 `[미확인]`.
6. 웹훅 `/api/webhooks/toss`: 본문 신뢰하지 않고 Toss 서버 재조회 후 처리. 서명 검증은 없음.
7. 모바일 결제는 명시적 미구현(501) — 웹 체크아웃 사용 유도.

### 1.6 캐싱·배포·환경변수

- **캐싱**: `unstable_cache` 태그 4종(site-content · testimonials · faqs · teachers), 재검증 5분. 관리자 CMS 변경 시 태그 재검증, 강사 캐시는 승인·프로필 변경 시에만 무효화.
- **Cron**: `check-alerts` 매일 00:00 UTC / `generate-monthly-reports` 매월 1일 01:00 UTC. `CRON_SECRET` 또는 `x-vercel-cron` 헤더 인증.
- **필수 환경변수**: `DATABASE_URL` · `DIRECT_URL` · `AUTH_SECRET` · `NEXTAUTH_URL` · `ADMIN_SETUP_SECRET` · `NEXT_PUBLIC_SUPABASE_URL/ANON_KEY` · `CRON_SECRET` · `ANTHROPIC_API_KEY`. 추가: `TOSS_SECRET_KEY`(프로덕션 미설정 시 confirm이 명시적으로 throw) · `SUPABASE_SERVICE_ROLE_KEY` · `DEFAULT_MANAGER_EMAIL` · `CHIEF_MANAGER_EMAIL` `[미확인]`.

| # | 항목 | 상태 |

| 9 | QnA 모델 이중화(`Question` DEPRECATED) · 웹–앱 journey drift · 합성 이메일이라 이메일 알림 불가 · pooler `connection_limit=1`로 병렬 Prisma 금지 | 잔여 정리 대기 |

## 3. 쟁점별 현황·권고

### 3.1 직거래 금지 — 기간·위약금 (강사 위촉 계약)

- **기간 12개월** 권장 — 경업·유인 금지는 기간·범위 과도 시 무효 위험, 24개월 이상은 위험 증가. 12개월이 중개 플랫폼 실무 통용 수준.
- **범위 한정 필수**: "회사를 통해 알게 된 학생·학부모"로 한정(초안 반영). 과외 활동 전체 금지는 직업 자유 침해로 무효 위험.
- **위약금은 "해당 학생 최근 월 수강료 4개월분" 단일 기준** — 민법 제398조상 손해배상액 예정으로 추정되며 실제 일실이익(월 기여마진 약 21.6만원 × 잔존 기대 수강기간)과 괴리되지 않아야 유지된다. 4개월분(약 260만원 내외)은 마진 기준 약 12개월치 일실이익 규모로 방어 가능 범위.
- "위약금 + 별개 손해배상 병존" 문구는 위약벌 해석 → 공서양속 위반 전부 무효 위험. **손해배상 예정 단일 구조로 단순화**(초안 반영).
- **학부모 측에는 위약금을 두지 않는다** — 소비자 상대 위약금은 약관규제법 제8조 무효 리스크. "직거래 시 재매칭 보증·환불 보장 등 회사 보증 종료" 수준의 불이익으로 설계.

### 3.2 강사 신원확인 — 조회 권한 범위

- 아청법 제56조상 성범죄 경력 조회 의무는 학원·교습소·개인과외교습자에 적용 — 당사가 중개·관리 플랫폼이라면 **직접 경찰 조회를 요청할 법적 근거는 불분명**.
- 실무 설계: ① 강사 본인 발급 「성범죄 경력 회보서(본인 확인용)」 위촉 전 제출, ② 개인과외교습자 신고 대상 강사는 신고증 사본 제출, ③ 수집 목적을 명시한 별도 동의서(L-4)로 근거 확보.
- 일반 범죄경력회보서(전과 전체) 요구는 형실효법상 수집 제한 논점 — **성범죄 회보서 + 신고증으로 한정** 권장.

### 3.3 학원법상 회사 지위

- 과외교습 신고 의무 주체는 **강사 개인**(학원법 제14조의2). 대학(원) 재학생은 신고 면제 — 재학생 중심 강사풀이면 상당수 면제, 휴학생·졸업생·전업 강사는 신고 필요.
- 회사는 매칭·학습관리만 제공하면 학원 등록 비대상이라는 것이 당사 모델의 전제. 경계 유지 조건: ① 광고·계약 문구에서 회사가 교습 주체로 보이지 않게("수업은 강사가 제공, 회사는 매칭·관리") — 계약 초안 반영, ② 매니저 업무를 상담·일정·리포트로 한정(교과 지도 아님).
- 행정: **통신판매업 신고** + 중개자 모델 선택 시 통신판매중개자 고지(전자상거래법 제20조). 유료직업소개사업은 위탁계약 매칭이므로 비해당으로 보는 것이 합리적이나 확인 필요.
- 강사 위촉 계약에 개인과외교습자 신고(면제자 제외) 의무 조항 반영 완료.

### 3.4 강사 정산 원천징수 (세무)

- 위촉 계약의 계속·반복 용역 → **사업소득 3.3% 원천징수**가 표준. 기타소득(8.8%) 처리는 부적절.
- 회사 의무: 원천세 익월 10일 신고·납부, 사업소득 간이지급명세서 매월 제출, 연간 지급명세서. 강사의 5월 종합소득세 신고 안내는 계약서에 반영.
