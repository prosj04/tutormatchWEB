## 1. 파일럿 계획과 시뮬레이션 결론

### 1.1 파일럿 골격 (2026-07 확정)

- **지역 = 서울·동탄 이핵 병행.** 단핵 집중 권고는 기각 — 필요 시 단핵 전환은 오너 재량이다. 전환 결정 시 대기 안내 문안(개시 시점 약속 금지)과 V-29 시즌 큐 등록 절차를 그대로 가동한다.
- **강사 배치 = 집중.** 분산(1강사=1~2학생) 안은 폐기됐다 (2026-07 확정 — 구 결정표의 "분산" 서술은 무효).
- **강사 채용 공고가 유입보다 6주 앞선다.** 공급이 병목이다. 지원서에 거주 동 + 이동 권역 필드(복수선택 1문항)를 공고 게시 전에 배포한다 — 배정·진입 판정의 공통 입력원.
- 리드 0·CAC 40만 원 도달 시 유입 중단 규율(주간 수기 점검).

### 1.2 용량 게이트 — 모든 유입·터치의 발동 조건

파일럿의 유입과 접촉은 아래 상한 안에서만 집행한다.

| 항목 | 상한 |
|---|---|
| 유입 상한 | 오너 처리용량 역산 — 상한 밖 리드는 대기 적재 |
| 터치 예산 | 방문 전 ≤3 · 상담 후~결제 ≤2 · 첫 30일 능동 ≤3. **자동 발송 4종 합산** 기준 |
| 강사 잔고 | 필요 수요 ×1.3 수기 유지 |

### 1.3 시뮬레이션 검증 이력 — 결론

1차(2026-07-04, 페르소나 실주행)와 2차(2026-07-05~13, opus 팀 도메인별 12라운드)를 거쳐 **수렴** 판정. 신규 P0/P1 0건, 회귀 0건, `tsc`·`lint`·`prisma validate` 전부 통과. 라운드별 상세는 `PILOT_SIM2_2026-07.md`(활성 원장).

**해소된 최우선 결함 (전부 수정 완료)**

- 크론 인증 우회 — `x-vercel-cron` 헤더 단독 신뢰 제거, `Bearer CRON_SECRET`로 통일.
- 매칭 무결성 — accept에 `PENDING_STUDENT_ACCEPT` 상태 강제, `manager/matches` POST에 담당·상담완료·구독 검증, 취소 매칭 재노출 차단.
- 미승인 강사 API 접근 — `requireTeacher`에 승인 게이트(온보딩 라우트만 pending 허용).
- 결제 서버 검증 — Toss confirm·금액 서버 검증·멱등성 구현. 환불은 Toss 실취소를 DB 전이 전에 호출.
- 웹 세션 재검증 — 전 가드에 소프트삭제·역할 강등 즉시 반영(모바일과 동일 정책).
- 숙제 자동분배 — 수동 분배 경로(플랜 탭, 4/7일 + repeatWeeks + 템플릿)가 기본. 첫 수업일 자동적용은 opt-in(`ENABLE_AUTO_HOMEWORK_DISTRIBUTION`, 기본 꺼짐). 분배는 보존·최소1·앞쪽 가중 불변식을 전수 검증 통과.

**1차 병목 진단(30명 동시 유입 가정)과 처리 결과**

1. 강사 승인 큐 1인 집중 → 매니저 승인 허용으로 해소. 거절은 하드삭제에서 softDelete로 교체.
2. 상담 완료 직렬화(완료 처리 전 매칭 준비 불가) → 미조치 잔여. 파일럿 중 관찰 대상.
3. 관측·소통 부재 → 신규 WAITING 알림·강사 배정 알림 구현. 즉시 알림 웹훅은 URL 대기(§3-7).

**방어된 기준선 (회귀 방지 기준)**

결제 멱등성·금액 서버 신뢰(`planIdFromAmount`), 결제→치프 자동배정, 배정 원자 처리(TOCTOU 없음), IDOR 소유권 검증, 소프트삭제 재로그인 차단, mass-assignment 방어, 극단입력 내성.

**잔여 기록 (수정 불요 판정 또는 후속 과제)**

- `nextStep`은 저장 전용 — 자동 매칭 이행을 원하면 별도 과제.
- report PUT의 COMPLETED 상담 편집 허용 — 완료 직후 리포트 작성이 자연 흐름이라 유지.
- 알림톡 템플릿 인프라는 데드코드 — 카카오 계약 시 활용, 정리 보류.
- days=7 분배의 주말 포함 — 선생님이 4/7일을 명시 선택하는 UX이므로 의도로 판정, 유지.
- 정산 환불 차감 로직 복제(공용 헬퍼 추출 후보), refresh 싱글플라이트 부재(성능만).

**인프라 반영 완료**: `connection_limit` 1→5(prod·로컬), CRON_SECRET prod 설정, SatisfactionCheckin 유니크 제약 적용, 파일럿 테스트 계정(pilot-/pilot2- 12개) 소프트삭제 정리. "규규"(010-0000-0000)는 오너 테스트 계정으로 보존.

**미해결(오너 액션)**: `ANTHROPIC_API_KEY` prod 미설정(§3-5), Toss 라이브 키는 계약 후 교체.

## 2. 매니저 운영 지침·SOP

모든 처리는 담당 매니저가 수행한다. CHIEF_MANAGER는 전 학생 관리가 가능하다. 학생 요청은 "매니저에게 문의" 버튼으로 접수되며, 시스템 장애·정책 변경은 치프에게 보고한다.

### 2.1 상담 3막 (무개발 — 즉시 운영)

1. **각본**: 목표 → 수준 → 성향 → 요금 → 다음 단계. 스크립트 흐름이 진단서 필드와 1:1 — 스크립트대로 하면 진단서가 채워진다. 골격만 표준화, 재량은 보존.
2. **상담 중 진단서 실입력** → 종료 시 **처방전 프린트 전달**.
3. **배정 근거 구술**: 왜 이 선생님인지 상담 자리에서 말로 설명한다.

상담·자료 전반의 검증 요소는 묻기 전에 먼저 안내한다 (2026-07-13 오너 확정):

- 담당 선생님은 범죄경력 회보서를 확인하고 배정합니다.
- 방문 수업은 배상책임보험 가입 상태에서 진행합니다.
- 첫 수업 후 매니저가 수업 품질을 직접 확인합니다.

원칙: 사실 서술만 — 확언체, 공포 소구·경쟁사 비교 금지. 노출은 상담 안내·로그인 후 화면 한정(공개 페이지 수정 금지), 조건·근거는 각주로. **대외 서사는 B — 대면·밀도·큐레이션으로 말하고, AI는 강사의 내부 도구로만 언급한다** (2026-07 확정).

### 2.2 배정·첫 30일 온보딩

- 방문 안내서 1장, 첫 수업 D-1 3자 문안, 마일스톤 체크, 저점 24시간 내 개입. 능동 터치는 첫 30일 ≤3(§1.2 예산 내).
- **위기 3색 신호등(주 1회 수기)**: 정상 / 주의(완수율 하락·리포트 미열람·취소 2회+) / 위험(연속 결석·불만·환불 문의). 자동화는 활성 15명+ 이후.
- **재매칭 트리거 3종**: 학생 미수락 48h · 강사 이탈 · 학부모 불만 — 각각 표준 대응 절차로 처리. 재배정은 무마찰 프로토콜(교체 비용 0원).
- **수업 QA**: 파일럿은 전수, 이후 매니저 주간 랜덤 감사(리포트 품질·숙제 적정성·수업확인 사유).
- **방문 안전**: 첫 방문 학부모 동석 권고, 가정 공용공간 원칙, 첫 수업 후 3자 확인. 절차 사실 서술로만 — 과한 강조는 공포마케팅.

### 2.3 팔로업 단일 파이프

자동 D+3 문안 = 처방전 재상기 → 매니저 수기 접촉 시 자동 발송 억제 → 미결제는 5분류 태깅(note 접두어 규약) → 시기미정은 시즌 큐 적재. CRM 접촉은 3터치 상한 합산 안에서만.

### 2.4 구독 일시정지

학부모에게 노출하지 않는 제도다. 불가피한 요청 시에만 매니저가 수동 처리한다.

- 허용: 1회 최대 30일(시스템 상한 35일), 연 2회 권장, 정당 사유(시험·여행·건강) 확인 후.
- 처리: `POST /api/manager/subscriptions/[id]/pause` body `{ action: "PAUSE", until: "YYYY-MM-DD", reason? }` / 재개는 `{ action: "RESUME" }`. 일시정지 기간만큼 만료일이 자동 연장된다 — 수동 연장 불필요.
- 기록: 사유·재개를 케어 로그에 남긴다.

### 2.5 상담 노쇼

1. 시스템이 24시간 전 리마인더를 발송한다. 무응답 신규 건은 수기 재확정 전화.
2. 상담 시간 경과 시 노쇼 전환 — 매니저가 알림을 받고 재연락한다.
3. 동일 학생 2회 노쇼 → 치프에게 보고, 학습 태도·계약 조건 재검토.
4. 사유 확인 후 재상담 일정을 제안한다.

### 2.6 선생 교체 요청

1. 요청 접수 후 사유를 기록한다.
2. 3일 내 학생과 통화 — 교체 이유 상세 확인, 현 선생님과의 개선 여지 검토.
3. 승인 시 새 선생님 배정 → 학생 통보 → 첫 수업 일정 조율.

### 2.7 선생 귀책 취소

시스템이 보충 수업을 자동 생성한다 — 매니저는 생성 상태를 확인하고(무음 실패는 응답 사유로 표면화됨) 학생에게 일정을 안내하며 학습 계획 영향을 조정한다.

### 2.8 케어 로그

- 주기: 학생당 주 1회 이상(최소 월 4회). 상담·모니터링·학습 진행·학생 관심사·선생님 소통 요약을 기록한다.
- 공개 범위: 긍정적·객관적 피드백은 학생 공개, 민감 정보·조직 판단은 매니저/치프만.
- 진단서·월간 리포트는 기구현 — SOP로 실입력과 cron 발송을 강제하고, 케어 로그를 리포트에 편입한다.

### 2.9 수업 확인 (2026-07 확정)

자동완료는 폐지됐다 — 구 문서의 "D+7 자동완료" 서술은 무효. 선생님이 완료/사유를 선택하고, 학생 과실은 정산 포함, 비과실은 마지막 수업으로 이월, 3자(학생·학부모·매니저) 알림. D+7 무응답도 **비과실 이월**로 처리한다 (코드 반영 완료, b820d20).

## 4. 구현 계획·리팩터링

### 4.1 확정 운영 방침 (구현의 상수)

1. 법률 문서는 별도 페이지 + 작은 고지·링크만. 문구는 플레이스홀더 — AI 창작 금지, 추후 실제 자문으로 교체.
2. 후기는 프로그램 안에서 수집하지 않는다. 대면 수집 후 Admin/CMS 수동 등록.
3. 학생은 수락만 한다 — 거절·재배정 UI/API를 만들지 않는다. 수락은 형식적 절차이며 UI·마케팅에서 강조하지 않는다 (구 "학생 수락 관문" 서술은 폐기). 재배정은 매니저 권한.
4. 보호자 동의는 "동의 간주" 고지 + 학부모 연락처 매니저 전달로 제한. SMS 인증·전자서명·미성년 분기 금지.

### 4.2 구현 세션 순서와 현재 상태

계획된 8세션 중 핵심 경로는 시뮬레이션 라운드를 거치며 구현·검증이 끝났다.
