## 4. 확인하지 못한 것

- 실기기·실브라우저 결제(Toss 위젯은 헤드리스에서 빈 영역으로 렌더 — 위젯 내부 무수정).
- 재현용 데이터가 없는 상태: 학생 여정 단계(매칭 중·배정 확인·첫 수업 대기)·상담 예약 화면(테스트 학생 2명 모두 ACTIVE 라 리다이렉트), 가입 모달 2단계, 결제 완료 처리 중 배너, 환불 모달, 선생님(TEACHER) 전용 화면. 코드 검토와 타입 검사로만 확인.
- `/dashboard?cms_edit=1` — 학생 대시보드 트리에 `SessionProvider` 가 없어 CMS 편집 모드가 에러로 뜬다. **개편 전부터 있던 문제**(개편 범위 밖이라 수정하지 않음).
- CMS 편집 모드(`/?cms_edit=1`)의 dev 콘솔 경고 — `CmsEdit` 오버레이(div)가 `<p>`·버튼 안에 들어가는 구조 경고. 개편 전 `LandingPageV2` 도 같은 구조였다. 프로덕션 동작 영향 없음.

## 5. 오너 결정 사안

1. **`/pricing` 카드 단위 표기** — CMS `pricing_page.card_per_month` 값이 "원 / 월"이다. BUSINESS_DIRECTION §5 는 "월"이 아니라 "(4주)" 표기. 홈 카드는 "원/1개월(4주)"(코드 폴백). CMS 문구라 손대지 않았다.
2. **홈 성과·합격 카드의 흰 배경** — 대학 로고·학교색 텍스트 가독성 때문에 다크 모드에서도 흰 카드로 남겼다(v2 와 동일). 토큰화하려면 지시 필요.
3. **`main` 병합·배포 시점** — 브랜치 `feat/editorial-redesign` 에 격리돼 있다. 병합 = 프로덕션 배포.
