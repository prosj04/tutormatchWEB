## 3. P2 — 이후 / 재검증 필요

- **커넥션 풀 취약성**: 시뮬레이션 중 `/api/notifications`·`/api/manager/monitoring`·`/api/admin/data/questions` 500은 코드 버그가 아니라 `connection_limit=1` 풀 고갈(병렬 부하)로 확인. 다만 monitoring처럼 쿼리 많은 엔드포인트는 동시 접속 수십 명에서 재현될 수 있음 → 쿼리 수 축소 or 풀 설정 재검토.
- **학생 로그인 간헐 실패 재검증**: Phase 1 에이전트는 동일 계정으로 로그인 성공, Phase 2 에이전트는 CredentialsSignin 실패. 풀 고갈 시점과 겹쳐 인증 쿼리 타임아웃이 원인일 가능성 — 단독 재현 필요. *(7/4 후속: 매니저 계정으로 단독 재현 시도 결과 서버 버그 아님 — NEXTAUTH_URL이 https 프로덕션 도메인이라 로컬 http에서 Secure 쿠키(`__Host-` CSRF)가 전송되지 않아 생기는 테스트 환경 아티팩트. 쿠키를 수동 전달하면 로그인 정상. 실서비스(https)에는 영향 없음.)*
- **매니저 계정 생성 경로 부재**: 강사 가입→admin 승격이 유일. 치프 매니저의 매니저 초대 기능.
- **학부모 계정/포털** (P1-1의 후속).
- **register/teacher/documents 무인증 업로드** — API_REFERENCE 기존 지적과 동일, REFACTORING_PLAN P0와 병합 관리.
