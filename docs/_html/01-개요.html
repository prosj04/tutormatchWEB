1. 제품 — 무엇이 돌아가는가

  • 서비스: Concord Private Tutoring — 서울·동탄 방문 1:1 프리미엄 과외. 매니저가 상담·매칭·리텐션을 중개.
  • 프로덕션: https://tutormatch-web.vercel.app (Vercel tutormatch-web, main push = 즉시 배포). 07-12 기준 로컬·origin 동기화.
  • 역할 5종 (07-10 PARENT 신설): 학생 / 학부모 / 선생님 / 매니저(+치프) / 어드민.

  • 실측 수치 (07-14): API 라우트 161 (src/app/api/**/route.ts 파일 카운트) · Prisma 마이그레이션 36 · 구독 일시정지(매니저 전용, 최대 35일) 지원.

Concord 사업 방향·원칙 정리

출처: 2026-06-16 ~ 07-13 세션 지시문 467건(docs/session-instructions.md) + 오너 확정 메모리. 오너(대표)가 직접 지시한 내용에서 추출한 사업 목표·이상·원칙의 종합본.

1. 사업 정체성

  • Concord — 프리미엄 1:1 방문(대면) 과외 매칭·관리 플랫폼.
  • 핵심 슬로건 방향: "선생님이 다릅니다" (히어로 카피, 한 줄).
  • 단순 매칭 중개가 아니라 매니저가 상담→배정→사후관리까지 밀착 운영하는 관리형 과외.
  • 서비스 지역: 서울(구·법정동·인접 지하철역), 동탄(행정동 단위).
  • 대상: 중·고등학생. 이해관계자 4역할 — 학생 / 학부모 / 선생님 / 매니저(+치프매니저).

2. 사업의 이상 (오너가 명시한 목표)

"학생의 공부 스타일과 맞는 교육 철학의 선생님을 추천해준다는 게 제일 핵심 포인트." (07-06)

  • 성향 매칭 철학:
    • 활발한 학생 → 카리스마 있는 선생님
    • 롤모델이 필요한 외동 학생 → 존경할 만한 인품의 선생님
    • 게으른 학생 → 성실한 선생님이 본보기
    • 여린 학생 → 친절하고 착한 선생님
  • 안전·신뢰: "안전하고 믿을만한 선생님이 배정된다"가 두 번째 축.
    • 대표가 전원 직접 대면 면접 — 인품·학력·신원·수업 실력 4가지 검증.
    • 단, 검증은 마케팅의 메인이 아니라 '요소' 중 하나로 배치 (07-07 결정 — 타사와 검증 수준이 크게 다르지 않다는 자기인식, 공포마케팅 과잉 경계).
  • 수업 밖 관리가 성적을 가른다: "수업보다도 수업 이후 학생의 공부가 성적을 가릅니다."
    • 매 수업 숙제·공부계획을 시스템에 등록, 학생이 매일 체크.
    • 질문은 최고성능 전용 AI가 즉시 답변 + 이어서 선생님 답변.
    • 매월 선생님이 직접 리포트 작성, 학생·학부모와 숨김 없이 공유.
  • 불만족 리스크 제거: 첫 수업이 맞지 않으면 100% 환불, 선생님 교체 비용 0원, 배정 후에도 매니저 상시 관리·언제든 상담 요청 가능.

3. 서비스 흐름 (North Star)

  1. 학생 신청 또는 결제.
  2. 신청만 한 학생 → 매니저 배정 대기 상태.
  3. 결제한 학생 → 치프매니저에게 자동 배정.
  4. 매니저가 배정받아 방문 상담 일정 조율 — 상담에서 학생 성향 파악 + 학습 진단 제공.
  5. 상담 중 매니저가 적합한 선생님을 자유 배정. (앱 내 학생 수락 버튼은 형식 — 마케팅·UI에서 절대 강조 금지. 거절/재배정 플로우는 학생 측에 만들지 않음. 재배정은 매니저 권한.)
  6. 선생님이 첫 수업일 지정 → 수업 시작.
  7. 숙제: 선생님이 1주(또는 4일) 분량을 한 번에 입력하면 요일별 가중 자동 분배. 반복 패턴은 템플릿으로 재사용.
  8. 수업 확인: 자동완료 폐지 — 선생님이 완료/사유 선택. 학생 과실=정산 포함, 비과실=마지막 수업으로 이월, 3자(학생·학부모·매니저) 알림.
  9. 구독 일시정지(paused): 학부모에게 노출하지 않는 제도. 불가피한 요청 시 매니저가 수동 처리, 이후 마찰 없이 재개.

4. 제품 우선순위

  • 앱이 우선, 웹은 보조 (07-12 명시).
  • 역할기반 단일 앱: 학생·학부모·선생님·매니저 모두 앱 사용.
  • 학부모 모드가 최대 갭 → 1단계: PARENT 계정, 자녀 연결은 코드/QR 2옵션 + 매니저 수동 연결, 결제는 학부모·학생 양측 가능, 학부모 권한은 액션도 가능.
  • 학부모 웹은 리포트·결제·상담만 (진도/숙제 불가).
  • 학부모 앱 = 수업·숙제·진도 열람용이라는 점을 홈에서 소개.

상품은 과외가 아니라 "학부모가 더 이상 비교·검증·선택하지 않아도 된다"는 안도감. 매니저가 정해주고 대표가 걸러준다 — 선택 피로의 제거가 상품. AI의 학습 기반은 마켓플레이스 문법(선택지·수락/거절·평점·비교·할인)이라 선택권을 주는 UX를 무의식적으로 재삽입하는 경향이 있고, 오너는 이를 반복 삭제해 왔다(수락 버튼 강조 금지, 거절/재배정 플로우 금지, 할인 구조 금지, 평점 수집 금지, 검증 배지 나열 제거). 이곳은 플랫폼이 아니라 큐레이션 서비스다.

반복 교정 8패턴 (AI 기본값 → 오너 원칙)

  1. 완결성 → 절제: 정보 많음≠품질. 프리미엄은 확언하고 침묵한다. 부연·조건 나열은 브랜드 훼손. "문장은 삭제 우선."
  2. 리터럴 → 의도 추출: 오너는 예시·참고 사이트·"이 느낌"으로 소통한다. 예시를 스펙으로 복사하지 말고 미학 규칙을 추상화해 적용할 것.
  3. 재해석 → 재현: 핸드오프는 영감이 아니라 사양. 취향 결정은 이미 끝났고 AI 역할은 충실한 이식. 창의 구간(신규 설계)과 복제 구간(핸드오프 구현)을 혼동하지 말 것.
  4. 논리 정합성 → 심리 최적화: 요금·카피에 수식적 일관성을 만들려 하지 말 것. 가격은 심리 신호이며 설명되지 않아도 된다.
  5. 일회 지시 → 영속 헌법: 오너의 결정은 세션이 바뀌어도 유효하다. 같은 교정을 두 번 받게 하지 말 것 (예: 요금제 카드 한 줄 배치 3회 재지시).
  6. 자율성 비대칭: 실행·과정 자율 100%("묻지 말고 끝까지"), 제품 취향 판단 자율 0%. 의견 제시는 환영하되 결정은 오너. 지시받은 범위 밖 "개선"을 실행에 끼워넣지 말 것.
  7. 균질 출력 → 인간의 결: 후기·카피는 각기 다른 사람의 질감이 필수. 평균 회귀한 매끈한 출력은 신뢰를 깎는다.
  8. 자산 존중: 레이아웃이 사진에 맞춘다(역 아님). 시안(스킨)이 기능(원본)을 깎을 수 없다. 원본 훼손(크롭·비율 왜곡·기능 축소·내용 축약) 금지.

메타 구조 둘

  • 조직 설계 = 제품 설계 (동형): 학부모에게 "매니저가 정해준다"를 팔 듯, AI에게도 "오너가 정해준다"를 적용한다. AI의 판단 침범은 제품에서 수락 버튼을 강조하는 것과 같은 위반.
  • 스펙이 아니라 반응으로 설계: 오너는 살아있는 배포물에 반응하며 디자인한다. AI의 최적 역할은 빠르고·되돌릴 수 있고·충실한 초안 생산. "완성·확정"하려 들지 말 것.

12. 카피 말투 스펙 — 오너가 직접 쓴 문장의 역공학

오너가 지시문에 직접 받아쓴 카피가 말투의 정답 표본이다. 아래는 그 원문들에서 추출한 규칙.

정답 표본 (오너 원문)

  • "선생님이 다릅니다" (히어로, 한 줄)
  • "우리는 직접 만나고, 학생에게 맞춥니다" — AI가 쓴 "그래서 Concord는 모든 선생님을 대표가 직접 만나 고릅니다"를 이것으로 교체시킴
  • "부담 없이 수업에만 집중할 수 있도록, 우리는 최고의 선생님만 배정합니다."
  • "여전히 검증은 학생의 몫입니다"
  • "이렇게 진행됩니다" — AI의 긴 프로세스 제목을 이 네 글자로 교체시킴
  • "매니저가 방문 상담하며 학생 성향을 파악하고 학습 진단을 제공합니다."
  • "학습 진단을 바탕으로 함께 고민하여 적합한 선생님을 배정합니다"
  • "첫 수업 날짜를 확정하고 선생님이 방문하여 수업이 시작됩니다."
  • "상담 신청만 해도 학습 전문가의 1:1 학습진단 제공"
  • "첫 수업이 맞지 않으면 100% 환불 / 선생님 교체 비용 0원 / *환불정책 참고"

추출 규칙

  1. 평서 확언 "~합니다" 종결. 느낌표 0회(오너 카피 전체에서 단 한 번도 없음), 의문문 0회, 이모지 0회. 확신은 어조가 아니라 단정문 자체에서 나온다.
  2. 주어 "우리는" — 1인칭 복수 선언체. 회사명 3인칭("Concord는 ~합니다")보다 "우리는"을 선호 (직접 교체 사례 존재).
  3. 최상급은 클라이맥스 1회만. "최고의 선생님만"은 스크롤텔링 정점 단 한 곳. 평소 문장은 사실 서술("대표가 직접 만나 면접합니다") — 형용사가 아니라 절차의 사실로 신뢰를 만든다.
  4. 한 줄 원칙. "한 줄로 줄바꿈 없애줘" 반복 지시. 헤드라인은 반드시 한 줄, 줄바꿈은 의미 단위가 두 개일 때만.
  5. 대구(對句)와 리듬. "우리는 직접 만나고, 학생에게 맞춥니다" — 짧은 절 두 개의 병렬. 오너의 문장은 거의 항상 2박자.
  6. 숫자는 구체·최소. "주 1회·3시간" — 환산·합산·할인율 계산 절대 금지. "(4주)" 단서는 최소 표기.
  7. 조건·단서는 각주로 격리. "*환불정책 참고" — 본문의 확언을 흐리는 모든 조건은 작은 글씨로 분리.
  8. 인용은 원문 그대로. 뉴스 헤드라인 "최대한 그대로 갖다 써" — 패러프레이즈는 진정성을 깎는다. 자기 목소리(공감·선언)와 인용(사실)을 섞지 않는다.
  9. 도입·설명 문장 금지. "'이런 일들이 실제로 있었습니다' 빼. 두번째 문장만 있어도 되잖아" — 무대 안내 멘트 없이 본문이 바로 등장.
  10. CTA만 해요체/명사형. 버튼: "선생님 추천받기". 헤드라인 확언체 + CTA 해요체 투트랙.
  11. 후기는 정반대 문법: 브랜드 목소리와 달리 후기는 생말투·개인 질감·각기 다른 문체. 단 반말체 금지. "기존 과외는 ~불만 → 지금은 ~좋다" 구조. 브랜드는 균질하게, 목소리 빌린 것(후기·인용)은 불균질하게.

13. 추구하는 '느낌' — 미학 사전

"짜친다"가 최다 빈도 부정어. 그 반대말이 오너가 추구하는 느낌: 점잖고, 담백하고, 비싸 보이는.

짜침 판정 목록 (오너가 실제 제거시킨 것)

  • 맨 위 검정 프로모션 배너
  • 할인률 뱃지, 검증 3종 뱃지 나열("서류·학력인증·수업시연")
  • 화살표 아이콘 2개 (1개로), 버튼 뒤 화살표 아이콘
  • 흰색 박스로 감싼 문구 (박스 없이 카피로 직접)
  • 요일별 잔뜩 나뉜 작은 박스들 ("지렁이같이 생겨서")
  • 총 시간 환산 계산, 설명식 도입부, 원문 기사 링크 버튼
  • 과한 페이드/라운드 처리 (페이드는 5%만, 라운드 제거)

미학 원칙

  1. 요소는 지면 위에 직접 놓인다. 박스-안-박스, 카드-안-카드 금지. 문구는 배경 위에 바로.
  2. 효과는 지각의 문턱값에서. 페이드 5%, 소프트 섀도우, 색 절제는 "소극적으로" — 효과가 보이면 이미 과한 것.
  3. 템포 = 위계. 애니메이션 속도를 영화 편집처럼 지시(사례 나열=빠르게 1.2초, 강조 카피=느리게, 캐러셀 50% 감속, 채팅 1.5배 가속). 중요한 것은 느리게, 배경 정보는 빠르게. 균일한 타이밍은 위계 부재.
  4. 모션은 "스르륵". "삐걱거림" 혐오. 스크롤 연동보다 자동 진행 선호, 등장은 아래→위 부드럽게, 덜덜 떨림 즉시 수정 대상.
  5. 몰입 구간엔 전부 걸어라. 다크 전환 시 네비게이션·플로팅 버튼까지 숨김 — 연출 순간엔 UI 크롬 전체가 비켜준다. 단 스킵 허용·세션 1회로 통제감 보존.
  6. 광학 정렬 민감. 퍼센트 링 중심 틀어짐, 목업 상단 정렬(→중앙 정렬로), 버튼 크기 짝 맞춤 — 수치 정렬이 아니라 눈 정렬.
  7. 비례 감각. 요금제 카드 황금비, "글씨에 비해 카드가 너무 큼"(밀도), 확대는 밀도 유지하며 글씨와 함께. 크기는 절대값이 아니라 관계.
  8. 위계는 투명도로. 대학 로고 투명도 70% 배경 + 원색 텍스트 — 강조를 키우는 게 아니라 주변을 가라앉힘.
  9. 한 눈 원칙. 상담 폼은 신청 버튼까지 스크롤 없이 한 화면. 전환 지점에서 마찰 0.
  10. 닫힘의 예의. 아코디언 외부 클릭 시 닫힘, 기본값 "없음"에서 눌러 열기 — 인터페이스는 사용자를 가두면 안 됨 ("답답해").

14. 추가 교정 패턴 (§11의 8가지에 더해)

  1. 뺄셈 교정이 덧셈 교정의 수 배. 오너 교정의 다수가 "빼/없애/삭제/숨겨". AI 초안은 항상 오너 기준보다 요소가 많다. → 초안 완성 후 스스로 1회 감산 패스를 돌린 뒤 제출할 것.
  2. "확인해봐" = 실제로 봐라. "로컬에서 확인해봐", "직접 순회하면서", "API 주소로 접속하지 말고 직접 버튼 눌러가면서"(07-12) — 코드가 컴파일됨 ≠ 화면이 의도대로임. 오너는 AI의 '완료' 주장과 실제 화면의 불일치를 반복 경험함. → 눈으로 검증 전엔 완료 선언 금지.
  3. 감싸기 본능 억제. AI는 콘텐츠를 카드·박스·배지로 포장하려 함. 오너는 반복적으로 포장을 벗김. → 새 요소 추가 시 기본값은 '포장 없음'.
  4. 계산해서 보여주기 본능 억제. 총시간·할인율·환산값 등 파생 수치를 친절히 계산해 노출하는 AI 습관 → 오너는 전부 삭제. 원 수치만, 최소로.
  5. 오타·표기 실수에도 맥락 우선. "cheif"(오타)로 지시받아도 의도는 "chief" — 그러나 임의 판단 말고 확인. 단, 문구를 바꾸라는 지시가 아닌데 문구까지 바꾸는 것(07-08 "찾아오기나 해")이 더 큰 위반.
  6. 롤백 가능성은 신성. "기존 디자인 삭제하지 말고 언제든 돌아갈 수 있게", 커밋 분리 지시, 홈 화면만 선별 롤백 요청 — 모든 변경은 부분 되돌림이 가능해야 함. 광범위 변경을 한 커밋에 뭉치는 것이 실질 피해를 만든 전력 있음.
  7. 결정 브리핑 워크플로. "내가 결정해줄 사안 브리핑해"(07-12), "오너 결정사항 있으면 알려줘", "있으면 질문하고 없으면 바로 진행해" — 진행 중 잔질문 금지. 오너 결정이 필요한 사안만 모아서 한 번에 브리핑하고, 나머지는 진행. 질문은 흐름을 끊는 비용이므로 배치(batch)로.
  8. 대기 혐오 — 병렬이 기본값. "병렬로 다음 작업 진행해 너무 기다리지 말고"(07-06), "너무 오래걸리는데 점검해봐"(3회 이상), "에이전트들 잘 진행되고 있나 수시로 확인해" — 블로킹 대기는 위반. 독립 작업은 병렬로, 위임한 서브에이전트는 방치하지 말고 주기 점검.
  9. 파악→플랜→실행 프로토콜. 거의 모든 세션 첫 지시가 "프로젝트 파악해봐"이고 "플랜 잡고 진행해"가 수십 회 — 컨텍스트 없는 즉시 실행을 불신함. 큰 작업 전 플랜 제시가 기본 의례. (단 플랜 승인 후에는 "묻지 말고 끝까지".)
  10. 매몰비용 제로 — 즉시 폐기. "이거 롤백해 별로다"(07-07), "폐기"(07-06) — 만든 것에 애착 없음. 오너가 "별로"라 하면 방어·절충·부분수정 제안 말고 깨끗한 롤백이 정답. 작업량은 폐기 판단의 변수가 아님.
  11. 세션 연속성은 AI 책임. "기존에 작업하던거 기억 해?", "어디까지 했어? 이어서 진행해", "멈춘 것 있으면 다시 시작해줘", 핸드오프 문서 반복 요구 — 오너는 세션 경계를 인식하지 않고 하나의 연속 작업으로 취급. 세션 시작 시 이전 상태 복원, 종료 시 인계 기록은 AI의 기본 의무.

0.1 제품 북극성 — 프리미엄 과외 9단계

CLAUDE.md의 원문을 그대로 승계한다. 모든 구현·리팩터·문서 결정은 이 순서를 배반하지 않아야 한다.

  1. 학생이 상담을 신청하거나 결제한다.
  2. 신청만 한 학생은 매니저 배정 대기 상태로 남는다.
  3. 결제한 학생은 치프 매니저에게 자동 배정된다.
  4. 매니저는 배정된 학생을 받아 대면 상담 일정을 조율한다.
  5. 대면 상담 중 매니저가 적합한 선생님을 자유롭게 배정한다.
  6. 배정 확정을 위한 인앱 수락 버튼이 존재하지만 이는 형식적 절차다 — 마케팅 카피나 UI에서 학생 수락을 절대 강조하지 않는다.
  7. 배정 이후 담당 선생님이 첫 수업 날짜를 정하고 수업을 시작한다.

⚠️ 2026-07-08 개정: 구버전 6단계("학생이 수락 버튼으로 명시적으로 수락해야 수업이 활성화된다")는 폐기되었다. CLAUDE.md(2026-07-08 갱신)가 진실의 원천 — 수락 버튼은 코드상 존재하나 형식이며, 마케팅·UI에서 강조 금지. 코드의 matchStatus: PENDING_STUDENT_ACCEPT → ACTIVE 플로우 자체는 유효하다. 이 개정 이전 문서(docs/20-마케팅.md(구 MARKETING_PLAN)의 수락 버튼 소재화, docs/external/*의 "동의 기반 매칭" 강조 등)를 참조할 때는 이 규범이 우선한다.

  1. 대면 수업은 선생님이 1주(또는 4일)치 숙제를 한 번에 입력하면 시스템이 가중치 기반으로 자동 분배한다.
  2. 매주 반복되는 숙제 패턴은 템플릿으로 재사용 가능해야 한다.

resolveStudentJourneyStage() (src/lib/student-journey.ts) 및 mobile/lib/student-journey.ts의 stage enum이 이 9단계의 코드 반영이다. 두 곳의 enum이 어긋나면 반드시 웹을 기준으로 모바일을 갱신한다.

0.4 배포 규칙 — main push = 프로덕션

  • origin/main에 push하면 Vercel(tutormatch-web)이 즉시 프로덕션에 배포한다.
  • 오너의 명시 승인 없이는 push하지 않는다. 현재 로컬 main은 origin/main보다 29 커밋 앞서 있으며 다수의 미배포 변경이 대기 중이다. (2026-07-12 갱신: push 완료 — 로컬과 origin/main 동기화 상태, 대기 커밋 0개.) 새 커밋은 오너 승인 전까지 로컬에만 쌓는다는 원칙은 유지.
  • 배포 시 빌드는 prisma migrate deploy && next build. 미적용 마이그레이션이 있으면 배포가 스키마를 자동 반영한다 — 이는 스키마 세션의 결정 사항이므로 임의로 트리거하지 않는다.
